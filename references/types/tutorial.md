# 实操教程

**使命**：看完能照着做。可复现、步骤清晰、有前后对比。
**风格**：主用实战复现、产业落地；辅以专业纵深；需要时加数据锚定；慎用观点锐度。

## 采集

1. 场景与目标
2. 前置条件：工具、材料、账号、环境、预算
3. 步骤概要
4. 踩过的坑和解决办法（越具体越好）
5. 前后效果对比
6. 版本信息、代码片段或示意图（软件类）
7. 发布平台

## 专业社区 / 公众号版

**标题**（以实战动作或效果为核心）：

- `[产品/服务/方法] + 实战/上手/落地 + 核心成果`
- `从[起点]到[终点]：[对象]的完整操作记录`
- `手把手教你用[对象]做到[目标]`

**开头**：场景痛点先行 + 解法预告，说清“要解决什么问题、在什么条件下”，不以“随着XX的发展”开头
**正文**：

1. 场景与目标
2. 准备：工具、材料、账号、环境、预算
3. 分步操作：每步一个动作，写操作 → 关键参数或要点 → 预期结果（缺图标 `[配图待补]`）
4. 踩坑与排查：现象 → 原因 → 解决
5. 效果验证：前后对比
6. 扩展用法与适用边界
7. 进一步资源：文档、客服、社群

各部分比例按实际步骤多少定。视角第一人称或团队均可，语气平等、实在、不端架子。

## 按主体调整

- **软件与 AI**：以命令、配置、接口为步骤；代码或指令有注释、可直接运行，不用伪代码糊弄；涉及密钥必须附安全提醒，截图打码。
- **消费品**：以使用、保养、搭配为步骤。
- **门店与工作室**：以“到店流程”“预约流程”“护理方法”为步骤。
- **非软件类通用**：材料和工具写清规格；火候、时长、力度这类经验给判断标准（“表面起小泡就翻面”），不只给一个数字。
- **公众号版**：减少代码细节，增加“为什么值得一试”。

## 系列化

统一比喻或叙事线；开头一句回顾前篇但可独立阅读；共享的准备步骤保持一致。
