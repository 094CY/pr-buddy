# 终检与交付（Step 6）

## 一、机械检查（脚本出结果）

```bash
R=<本 Skill 目录>/references
python3 $R/wordcount.py <稿件.md>                       # 字数，头部只写它给的数字
python3 $R/article_lint.py <稿件.md>                    # 常规稿件
python3 $R/article_lint.py <稿件.md> --short            # 短视频脚本：不查头部
python3 $R/article_lint.py <稿件.md> --short --no-card  # 配文：不查头部和论证卡
```

- **ERROR**（头部格式、字数偏差、重复句、时间标记、待确认未列清单、论证卡缺失或有空项、写了“回应不了”却未收窄）修到 0 再交付。脚本只核对论证卡写没写，写得对不对由 Step 4.5 判定负责。
- **REVIEW**：绝对化、医疗与功效、承诺与保证、价格与促销用语每处都要确认（有依据、不踩类目红线、规则写清）；AI 痕迹信号只列反复出现或同段叠用的，逐条看语境，该改改、该留留。

## 二、定稿后生成成品

用户明确确认定稿（“定稿”“可以了”“没问题了”）后才执行：

```bash
python3 $R/md_to_docx.py <定稿.md> [输出.docx]    # 转 Word，自带字体校验
python3 $R/md_to_docx.py --check <文件.docx>      # 单独校验已有 Word
bash $R/check_markdown_html_consistency.sh <定稿.md> <公众号.html>   # HTML 零改写校验
```

Word 规格：字体 Microsoft YaHei 四项全设，正文 10.5pt，H1 18pt，H2 14pt，H3 12pt，1.5 倍行距。公众号 HTML 每次生成或修改前重读 `wechat-html-template.md`，配色和组件以它为准。

## 三、判断检查（读稿逐项判断，发现问题当场改）

| 维度 | 检查什么 |
|------|---------|
| **1 标题** | 准确反映主题、不标题党；有钩子，媒体稿不搞悬念，种草和公众号不写官方体；格局不低于正文；有信息量；3 条备选各有侧重 |
| **2 主题** | 核心信息与论证卡一致，成立依据在正文都有体现，受众价值写进了正文；全文紧扣主题，没有跑题或喧宾夺主的段落 |
| **3 逻辑** | 各章结论支撑核心论点；新概念交代了与主线的关系；收尾不打脸；时间判断前后一致；因果链不跳步；没有给受众科普早就知道的东西 |
| **4 观点与品牌安全** | 不贬低同行；无敏感类比；无可能被断章取义的表述；责任主体没有被转移；整体符合 Step 1.5 判定的品牌调性 |
| **5 事实数据** | 逐句扫“当前状态、普及程度、行业趋势”类判断；数字、价格、排名、评分、客户名、产品名、门店信息都核过；评价和案例有真实来源并可公开；查不到的标 `[待确认]` |
| **6 结构** | 以类型文件为基线而非模具：核心模块齐全；无零信息量的模块；开头建立了阅读预期 |
| **7 前后一致** | 名称、数字、价格、人称、时态全文一致 |
| **8 合规与 CTA** | 对照 `compliance-notes.md`：正文没有出现论证卡「合规边界」写明不写的内容；绝对化表述、价格比较有依据；“免费”“赠送”“限时”写明条件；商业合作可识别；CTA 软硬与类型匹配，行动路径正确；收尾视角与开头一致 |
| **9 去 AI 痕迹** | 处理完 REVIEW 项；大声读一遍，像机器在总结、像说明书在念卖点的段落改掉 |
| **10 需求回检** | 用户的每一条要求（字数、风格、结构、口径）是否满足 |
| **11 信息缺口** | 全文所有 `[待确认]` 都列进信息缺口清单，没有漏标的 |

维度 1、2、3、5、8 不过，按 SKILL.md「回退」处理。

## 四、交付说明（写证据，不打勾）

1. **文件**：路径；主标题及选择理由；主体类型与调性依据；内容类型与渠道（自动判断时说明依据）。
2. **写前论证卡**：核心信息；最强质疑与回应；受众价值；合规边界（照抄卡里的实际内容）。
3. **脚本结果**：字数；lint 的 ERROR / REVIEW 数，REVIEW 里改了哪些、留了哪些及依据；HTML / Word 校验结果（如涉及）。
4. **判断层发现**：终检中发现并已修正的问题（没有就写“未发现需修正的问题”）。
5. **信息缺口与发布提示**：`[待确认]` 条目；敏感类目提醒发布前走法务或平台审核；商业合作内容提醒按平台要求标注；没有就写“无”。
6. 适用时一句话提议：是否需要配套配文。

用户明确只要成稿时，可只保留第 2、3、5 项。
