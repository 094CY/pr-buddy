# 渠道特征与结构原则（Step 3）

> 各类型的具体结构在 `types/` 对应文件里，本文件只管渠道差异和通用结构原则。

## 八个渠道

| 渠道 | 特征 | 语气 |
|------|------|------|
| **媒体发布** | 5W1H 开头，信息密度高，可直接转载；优先讲“事实 + 结论” | 官方、克制、事实密度高 |
| **公众号** | 标题有钩子，开头抓痛点，段落短，有转发欲；优先讲“痛点 + 变化 + 价值” | 专业但不端着，像懂行的朋友在聊 |
| **短视频平台** | 脚本化、口语化，前几秒定生死 | 像在跟人安利一个好东西 |
| **图文种草社区** | 首图和标题决定点击，正文要有体验细节和实用信息 | 像真人分享，第一人称只用于真实体验 |
| **本地生活平台** | 点评、团购、地图页；看的人在做“去不去、买不买”的决定 | 信息直给：地址、营业时间、套餐、规则 |
| **官网与电商详情页** | 结构化、可检索，卖点与参数并列 | 精确、零废话 |
| **专业社区** | 技术社区、行业论坛、问答平台；实战导向 | 行家对行家，平等对话 |
| **社群/朋友圈** | 极简、有钩子 | 像转发给朋友时说的那句话 |

标题、导语、小标题、CTA 的语气与渠道一致，不要“标题像种草笔记，正文像公文”。

## 结构原则

类型文件里的结构是经验基线，不是刚性模具；矩阵里的 `[主体]` 指本次的企业、品牌、门店、工作室或机构名称。

1. **内容驱动结构**：模块写多少以信息量和叙事节奏为准，信息不足绝不凑段。
2. **渠道建议非强制**：复杂论点需要完整展开时，保持完整优于强行切碎。
3. **模块可增减**：无内容可写就跳过，需要别的模块就增加；但促销文案的规则、声明的事实与措施、案例故事的困境与结果属于核心模块，不能省。
4. **风格可混搭**：同一篇里部分偏叙事、部分偏数据，只要节奏通顺。
5. **用户结构优先**：用户指定了结构或大纲时，以用户为准。
6. **跨渠道做模块迁移**：同一主题要发多个渠道时（通稿 → 公众号 → 种草 → 短视频），按目标渠道重组模块，不整篇硬改。
